# Development v0.15.0: persistent bedside scene

Deployment target: `clinical-encounter-v0.13` only. The other published branches are outside this release.

## What changed

- The patient scene occupies the viewport. A separate console over the right side holds Talk, Examine, Tests, Treat and the encounter record. On narrow screens the scene remains above the console. The monitor has a dark electrical trace and current simulation values.
- ECG acquires a twelve-lead recording at the current simulation time. Recordings are stored in `state.diagnostics.ecg`, retained with the clinical record and downloadable as SVG. Viewing a previous recording cannot change it. Acquisition does not advance simulation time in this version.
- Changes in documented consciousness, breathing effort, mottling or active respiratory interface trigger an edit of the original patient photograph. Every edit references the original image to reduce identity drift. Merely changing a number or suspecting a diagnosis cannot add a physical sign.
- Image requests run in the background, one at a time per encounter. Each result is associated with its captured appearance state. Results from an earlier state cannot become the current photograph for a different state. Up to eight images are cached per session, with the original reference retained separately.
- While an edit is pending or fails, an earlier photograph is explicitly identified as previous; current observations and monitor values remain available. Retry is available on failure. Image generation never advances clinical time or blocks treatment.
- A sedated, obtunded or unresponsive patient cannot supply new spoken history. Previously acquired history remains in the clinical chart.

## Clinical scope and limits

See [ECG_MODEL.md](ECG_MODEL.md) for the signal model, supported rhythms/profiles, source references and exclusions. These are **unvalidated educational waveforms**, not de-identified real recordings. This release does not establish the information content or diagnostic accuracy of a real ECG. It does not add new ACS/PE clinical scenarios or their treatment trajectories to the existing problem generator. Only a case-authored electrical profile can select an ST or right-strain pattern; learner suspicion cannot.

Photographs are AI illustrations of documented observations. Their anatomy, identity preservation and clinical expression have not been verified by automated image checks: those checks validate image format and dimensions only. A still image cannot establish responsiveness to stimulation, skin temperature, capillary refill duration or breathing motion. Examination remains available to obtain those findings. Image updates have provider latency; this is not continuous animation or a guarantee of immediate visual transition. Images are session-local and not restored from saved encounter records.

The image edit implementation follows the [OpenAI Images edit API](https://developers.openai.com/api/reference/resources/images/methods/edit). Streamlit's [fragment API](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment) polls completion while the learner continues interacting.

## Verification

Automated checks cover acquisition immutability, lead identities/calibration and explicit profile selection; image state/source constraints, malformed image rejection and out-of-order completion; plus problem selection, conversation, examination and management access through Streamlit AppTest. Actual provider images are not generated by the test suite.

The available browser could not access the local preview (`ERR_BLOCKED_BY_CLIENT`). Therefore viewport appearance, mobile sizing and live provider image fidelity still require visual review of the development deployment. Do not treat AppTest as browser layout or clinical validation.
